# Piper-L π0.5 + RLT

此入口使用 Yyshadow/openpi-RLT 的原始 RLTokenModel、ChunkActor、TwinCritic 和 actor-critic 更新实现。源码固定在 `c1e40ac360185778c98cf20da2820e22d2d415e7`，保留 Apache-2.0 许可证和来源记录。Piper 接口位于独立 `rlt_piper/`；原π0.5、VPP2、Corrector入口不变。本次用户选择先不用Corrector，因此此入口不加载其权重、不运行其监控或引导。

## 已有模型与训练阶段

基础模型始终为当前2500更新的π0.5，50步、30Hz、六关节弧度和绝对夹爪米。主干冻结，不覆写原权重。Token读取冻结VLA最终Transformer的两路有效图像前缀（512×2048）；固定屏蔽的第三路图像被移除，语言/状态仍参与前缀注意力。使用上游Encoder/Decoder训练512维Token。

离线准备使用原48训练/6验证的整段划分，每6帧取一个不跨episode的锚点，八H100提取后训练Token1000步。留出重构MSE为0.659724，初始22.1516；该验证集不构成RL成功率证据。此阶段不训练在线actor，不执行机械臂。Token完成后训练进程退出并释放显卡。

在线学习在 .102 的单张 5090 上进行，基础 π0.5 和 Token 冻结，只训练上游 18 步 ChunkActor/TwinCritic。此入口不加载 VLA-Corrector。首次没有 actor 时明确打印 base warmup，先由 π0.5 控制；回放达到 600 个完整有效 transition 后后台训练，前 2000 步 BC 权重 5、Q 权重 0，随后 Q 权重 0.1。达到 warmup 后才允许 actor 接管策略输出；不会执行随机初始化 actor。

## 人工在环训练命令

在 `.102` 执行（会自动准备、对齐并开始真实动作，不再输入 RUN）：

```bash
cd /home/arm/piper_pi05_rtc_cmd_20261112
./run_pi05_rlt.sh --stage online
```

- `I`：策略与人工接管之间切换。接管清空 RTC 队列并使旧在途推理失效；主臂 can0 相对接管瞬间的位置控制从臂 can1，初始目标保持从臂当前指令位置。夹爪沿用数采程序的闭合偏移、缩放和范围校验，再做相对映射。交还时保持当前位置，等待交接之后的新图像、新状态和新 chunk，再通过既有 RTC 桥接和平滑进入策略。
- `S`：整轮成功；`F`：整轮失败。两者结束本轮并阻尼停止。下一轮重新运行同一命令，学习状态自动恢复。
- `Space / Esc / Ctrl+C`：独立固件阻尼急停，保持原来的 `0x150/01` 路径，不发 Disable，不把急停标成成功。

主臂须已按桌面数采程序配置为可拖动并输出控制帧，退出数采后再运行本入口。入口只读取 can0，核对 USB-CAN 身份、1Mbps 和共享锁；不发送主臂使能、角色切换或模式恢复命令。主臂数据失效时停止，不用过期数据继续跟随。I/S/F 读取桌面 X11 物理键，不抢占原急停的终端输入；请只在训练时使用这些全局快捷键。

`--stage collect` 始终由原 π0.5 控制，也支持接管和后台训练，但本轮不激活学习 actor。`--stage online` 从明确的 base warmup 自动过渡到训练好的 actor。`--stage eval` 要求已有就绪 actor，使用均值且不训练。`--no-train` 禁用后台更新。原 `run.sh` π0.5 路径保持不变。

保存观测的检查（不打开 CAN/相机）仍为 `./check_pi05_rlt.sh --stage collect`。手动离线更新可运行 `PYTHONPATH=. .venv/bin/python -m rlt_piper.cli train`，与在线 learner 使用同一排他锁。

## 实时记录、训练和参数切换

仍使用 30Hz 动作时间轴、18 帧有效前缀、12 帧速度桥接、50ms 持续滤波以及 120Hz 唯一从臂发送线程。接管保留限速、实时固件范围和独立阻尼监督器。交接时只重置输出滤波的旧运动状态，后续 chunk 到达不重置滤波。

每次实际成功提交 CAN 后记录量化指令、时间、来源（base/RLT/human/hold）、控制代次、主臂目标和主臂帧时间；同时保存参考动作、Token、捕获对齐状态、actor 版本、交接事件和独立 S/F 结果。数据在私有 `rlt_episodes/`，每 2 秒发布一次原子快照，磁盘 I/O 不放进 120Hz 发送线程。快照完整后才更新 manifest，读取者按 manifest 版本加载。记录失败会停止执行。

人工片段默认是正向纠正示范：上游 HUMAN 来源让 actor 的 BC 目标使用实际发送的人工动作，普通策略片段的 BC 目标仍为基础 π0.5 参考动作。训练 batch 有人工数据时预留一半给人工纠正。人工接管不产生额外成功奖励；非终止片段奖励 0 并 bootstrap，只有明确的 S/F 终止才写入任务奖励。成功/失败后的最终快照会替换同一 transition 的临时版本。未标记急停后只保留完整、有效的人工纠正窗口，不伪造终止。跨控制代次、hold、Corrector、过期数据和不完整的非终止窗口均排除。

后台 learner 与推理共用同一 GPU 上下文和优先调度器：推理优先，每次只允许一个已预编译梯度步进入 GPU，约每 50ms 检查一次更新机会；单步超 50ms 或数值异常则暂停学习并明确记录，当前控制策略继续，原控制和推理看门狗仍生效。初始化和训练 JIT 编译在模型 ready、机械臂准备之前完成。首次 2000 步 warmup 后，每新增 transition 增加一个更新额度；数据不足时等待。

学习参数每 20 步发布到进程内 pending 槽，只在下一次完整 chunk 推理开始时激活；同一 chunk 全程使用一个参数版本。已有队列与新 chunk 由原 RTC 桥接和平滑衔接。每 100 步及退出时保存不可变 `generations/step_*`，最后原子替换 `CURRENT` 指针，避免 actor 参数与 metadata 跨版本。训练结束后只关闭本次创建的模型进程。

Token、actor、learner 状态和数据均不提交 Git。原论文的动作频率、chunk 和采样设置与本机适配不同，不能把无硬件通过等同于真实抓取效果提升。

## 本地桌面 UI

```bash
cd /home/arm/piper_pi05_rtc_cmd_20261112
./run_pi05_rlt_ui.sh
```

窗口打开后保持待机，不启动机械臂。选择在线训练、基础策略采集或 actor 评估，再点“启动本轮”会自动准备、对齐并执行。可在界面切换人工接管/交还、S/F 标记本轮结果以及阻尼急停；原 I/S/F 和独立 Space/Esc/Ctrl+C 全局键保持有效。界面显示双相机预览、实时关节/夹爪状态、推理延迟、有效回放/人工纠正窗口数量、训练步数、actor 版本及控制/模型日志。

“只检查模型 · 不动臂”只执行既有保存图像检查，不打开 CAN 或相机。预览复用正在运行的 CaptureBank，每秒最多更新一次，不额外占用相机；预览编码和 UI IPC 均不放进 120Hz 发送线程。

UI 使用私有 Unix socket 向原控制进程提交命令，控制进程仍唯一拥有从臂发送权。准备阶段不接受接管或结果标记；交接命令检查控制代次，重复或过期命令不会切换模式。心跳超过 1 秒或连接断开会设置原 Guard 的停止锁，使用原独立阻尼路径。关闭窗口先请求停止、等待子进程保存和退出，不用强杀代替阻尼停止。UI 不接管、停止其他程序的任务。

界面使用系统 Python/Tk，不向模型环境增加依赖。`./run_pi05_rlt_ui.sh --demo` 仅操作模拟状态，绝不启动控制器、推理或训练，可用于展示和布局检查。
