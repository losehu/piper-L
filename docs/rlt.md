# Piper-L π0.5 + RLT

此入口使用 Yyshadow/openpi-RLT 的原始 RLTokenModel、ChunkActor、TwinCritic 和 actor-critic 更新实现。源码固定在 `c1e40ac360185778c98cf20da2820e22d2d415e7`，保留 Apache-2.0 许可证和来源记录。Piper 接口位于独立 `rlt_piper/`；原π0.5、VPP2、Corrector入口不变。本次用户选择先不用Corrector，因此此入口不加载其权重、不运行其监控或引导。

## 已有模型与训练阶段

基础模型始终为当前2500更新的π0.5，50步、30Hz、六关节弧度和绝对夹爪米。主干冻结，不覆写原权重。Token读取冻结VLA最终Transformer的两路有效图像前缀（512×2048）；固定屏蔽的第三路图像被移除，语言/状态仍参与前缀注意力。使用上游Encoder/Decoder训练512维Token。

离线准备使用原48训练/6验证的整段划分，每6帧取一个不跨episode的锚点，八H100提取后训练Token1000步。留出重构MSE为0.659724，初始22.1516；该验证集不构成RL成功率证据。此阶段不训练在线actor，不执行机械臂。Token完成后训练进程退出并释放显卡。

在线学习在 .102 的单张 5090 上进行，基础 π0.5 和 Token 冻结，只训练上游 18 步 ChunkActor/TwinCritic。此入口不加载 VLA-Corrector。首次没有 actor 时明确打印 base warmup，先由 π0.5 控制；回放达到 600 个完整有效 transition 后后台训练，前 2000 步 BC 权重 5、Q 权重 0，随后 Q 权重 0.1。达到 warmup 后才允许 actor 接管策略输出；不会执行随机初始化 actor。

## 人工在环训练命令

在 `.102` 执行（会自动准备、对齐并开始真实动作，不再输入 RUN）：

```bash
cd /home/arm/piper_pi05_rtc_cmd_20261112
./run_pi05_rlt.sh --stage online
```

- `I`：接管时先清空 RTC 队列、失效旧推理，并在下一个控制周期固定从臂当前实测姿态（投影到固件指令范围），取消输出滤波的旧运动状态。确认从臂静止后，自动低速把主臂六关节对齐到该姿态。主臂到位、恢复拖动且获得稳定新反馈后，才切入人工跟随。六关节使用绝对姿态；从臂夹爪保持原开度，手持夹爪仅作为相对输入，不由程序电动开合。人工跟随中再按 I 交还策略，保持当前位置并等待新观测、新 chunk 后平滑恢复。对齐中按 I 会取消本轮并请求停止；UI 对齐中禁用重复接管按钮，保留阻尼急停。
- `S`：整轮成功；`F`：整轮失败。两者结束本轮并阻尼停止。下一轮重新运行同一命令，学习状态自动恢复。
- `Space / Esc / Ctrl+C`：独立固件阻尼急停，保持原来的 `0x150/01` 路径，不发 Disable，不把急停标成成功。

主臂须已按桌面数采程序配置为可拖动并输出控制帧，退出数采后运行本入口。核对 can0 USB-CAN 身份、1Mbps 和共享锁。自动对齐前读取主臂固件、实时关节限位：只接受明确支持无缝模式切换的 >=1.8.5 固件；不会采用“先 Disable/复位再使能”的旧路径。主臂需要处于已使能状态，控制/驱动反馈不满足条件则停止。按 I 后主臂将自动运动，请松开手柄让开；从臂保持稳定确认后还有 2 秒主臂运动提示阶段。I/S/F 从桌面 X11 读取，原急停终端通路保持有效。

主臂运动在独立线程执行，目标速度不超过 5°/s、轨迹加速度上限 10°/s²，采用端点速度/加速度为零的五次插值。每个目标与实时反馈到该目标的扫掠都做检查。到位误差 <=0.5° 稳定 300ms 后恢复主臂拖动，再核对新主臂数据与目标误差 <=1°。主臂缺反馈、跟踪偏差、从臂保持偏移、路径检查失败或任何急停均终止流程。独立 can0 监督进程监测共享停止锁和控制心跳，主臂受控后与原 can1 监督器分别发送 `0x150/01`，不发送 Disable。

`--stage collect` 始终由原 π0.5 控制，也支持接管和后台训练，但本轮不激活学习 actor。`--stage online` 从明确的 base warmup 自动过渡到训练好的 actor。`--stage eval` 要求已有就绪 actor，使用均值且不训练。`--no-train` 禁用后台更新。原 `run.sh` π0.5 路径保持不变。

保存观测的检查（不打开 CAN/相机）仍为 `./check_pi05_rlt.sh --stage collect`。手动离线更新可运行 `PYTHONPATH=. .venv/bin/python -m rlt_piper.cli train`，与在线 learner 使用同一排他锁。

## 实时记录、训练和参数切换

仍使用 30Hz 动作时间轴、18 帧有效前缀、12 帧速度桥接、50ms 持续滤波以及 120Hz 唯一从臂发送线程。接管保留限速、实时固件范围和独立阻尼监督器。交接时只重置输出滤波的旧运动状态，后续 chunk 到达不重置滤波。

每次实际成功提交 CAN 后记录量化指令、时间、来源（base/RLT/human/hold）、控制代次、主臂目标和主臂帧时间；同时保存参考动作、Token、捕获对齐状态、actor 版本、交接事件和独立 S/F 结果。数据在私有 `rlt_episodes/`，每 2 秒发布一次原子快照，磁盘 I/O 不放进 120Hz 发送线程。快照完整后才更新 manifest，读取者按 manifest 版本加载。记录失败会停止执行。

人工片段默认是正向纠正示范：上游 HUMAN 来源让 actor 的 BC 目标使用实际发送的人工动作，普通策略片段的 BC 目标仍为基础 π0.5 参考动作。训练 batch 有人工数据时预留一半给人工纠正。人工接管不产生额外成功奖励；非终止片段奖励 0 并 bootstrap，只有明确的 S/F 终止才写入任务奖励。成功/失败后的最终快照会替换同一 transition 的临时版本。未标记急停后只保留完整、有效的人工纠正窗口，不伪造终止。跨控制代次、hold、Corrector、过期数据和不完整的非终止窗口均排除。

后台 learner 与推理共用同一 GPU 上下文和优先调度器：推理优先，每次只允许一个已预编译梯度步进入 GPU，约每 50ms 检查一次更新机会；单步超 50ms 或数值异常则暂停学习并明确记录，当前控制策略继续，原控制和推理看门狗仍生效。初始化和训练 JIT 编译在模型 ready、机械臂准备之前完成。首次 2000 步 warmup 后，每新增 transition 增加一个更新额度；数据不足时等待。

学习参数每 20 步发布到进程内 pending 槽，只在下一次完整 chunk 推理开始时激活；同一 chunk 全程使用一个参数版本。已有队列与新 chunk 由原 RTC 桥接和平滑衔接。每 100 步及退出时保存不可变 `generations/step_*`，最后原子替换 `CURRENT` 指针，避免 actor 参数与 metadata 跨版本。训练结束后只关闭本次创建的模型进程。

Token、actor、learner 状态和数据均不提交 Git。原论文的动作频率、chunk 和采样设置与本机适配不同，不能把无硬件通过等同于真实抓取效果提升。

## 主臂手持夹爪碰撞模型与边界

数值模型在 `rlt_piper/leader_geometry.json`，包含完整来源和网格哈希：Piper-L 臂身来自 [官方 agx_arm_urdf](https://github.com/agilexrobotics/agx_arm_urdf) `680fa925cd00db7e2628563d2edc5540963045de`；示教夹爪参考 [官方 mobile_aloha_sim](https://github.com/agilexrobotics/mobile_aloha_sim) `f799ae0192c0c2bbd502ec4d9bbec8c2633acd1a` 的 `piper_master_meshes/link6/7/8.STL`，不是普通作业夹爪。

臂身用每个官方 STL 的包围盒。示教末端用覆盖整个开合行程、对法兰绕轴安装角度不敏感的保守包络（局部横向各 ±180mm、轴向 0~120mm），每个碰撞体再留 15mm 余量；这是刻意加大的检查体，并非声称实物宽 360mm。只继承 [官方 Piper-L SRDF](https://github.com/agilexrobotics/agx_arm_sim/blob/f8cd8b147c75d59e14f90fb0646770eefa268ed0/Moveit2/piper_l_gripper_moveit_config/config/piper_l.srdf) 的臂身排除项；普通夹爪的排除项没有套给示教手柄。工具/腕部连接面排除通过两侧半空间分离做数值验证，不能只修改配置跳过检查。

起点、终点和整条关节路径都检查自碰撞及基座安装平面。直线路径被挡时进行有时间上限的 RRT 搜索，所有扩展重新扫掠检查；使用运动半径界限与自适应细分覆盖采样间运动。目标自身碰撞或找不到路径就拒绝执行，不通过裁剪目标或缩小夹爪绕过。较大包络会保守地拒绝部分实际可能可行的姿态。

这里不包含未经测量的两臂安装外参、桌面障碍物或人的几何体；自碰撞软件检查不等于实际场景的完整防撞保证。本次只有几何、协议模拟和软件控制验证，没有打开机械臂做自动对齐验收。

自动对齐的初始姿态使用 `0x2A5/0x2A6/0x2A7` 实测反馈，不要求静止主臂持续发送 `0x155/0x156/0x157/0x159` 示教帧；恢复拖动后才检查新鲜的示教帧。实测关节边界允许最多 0.1° 偏差，但每个发送目标及规划目标仍必须在限位内，实际姿态到边界目标的扫掠仍检查碰撞。若当前主臂姿态的包络碰撞，拒绝自动移动，需要手动展开后再尝试接管。

接管时立即丢弃旧队列，持续发送接管瞬间的实测姿态作为保持目标，不再继续执行原策略。停稳期间仅用上一条已发送指令和保持目标之间的关节范围（外加原 1° 监测余量）检查残余运动；这不会重新发送上一条动作，也不会让保持目标追随漂移。实测关节必须在目标 0.5° 内、最近 0.22 秒波动不超过 0.1°、夹爪误差不超过 3mm，并持续确认 0.3 秒，才开始主臂对齐；3 秒未停稳则停止。开始对齐后，仍以原 1° 检查从臂保持偏移。界面会明确显示“等待从臂实测停稳，主臂未启动”。

几何模型可用 `training/export_leader_collision.py --urdf-source ... --aloha-source ... --sim-source ... --output ...` 从上述三个固定版本的官方仓库复现，导出器拒绝不同版本，已验证与部署 JSON 一致。2026-11-16 最终无硬件回归运行 164 项，163 项通过、1 项跳过；主臂受控定位和恢复拖动仅做协议模拟，未做真机运动验收。

## 交接静止段的训练裁剪

`rlt_piper/trimming.py` 在原始单调时钟上生成训练有效区间，不改写原始轨迹，也不把删除区间前后的动作拼成一条连续动作。明确的 hold/对齐阶段始终排除；每次策略/人工控制段的前后，还依据实际发送的指令和可用的实测关节/夹爪反馈裁掉交接长等待。初始启动等待也按同样规则处理。

默认关节变化阈值 0.05°、夹爪变化阈值 0.3mm、运动检测窗口 0.25 秒；仅对超过 0.75 秒的交接边缘静止作裁剪，并在动作边缘保留 0.25 秒上下文。夹爪单独动作也计为运动，纠正中间的任务停顿不做整段删除。仅有短停顿时保留；未标记交接边界的旧记录不盲目猜测删除。

在线回放会先暂存当前控制段尚未确定的静止尾部：后续继续运动时，内部暂停重新成为有效数据；发生交接时，则排除这段尾部等待，避免先送去训练再删除。S/F 与终止观测仍使用原始时钟；若最终控制段完全静止，最多保留一个 18 帧终止上下文，保持任务奖励的可学习性。训练窗口及其 bootstrap 状态都不得跨进被裁掉的区间。

新回合的 `episode.json.training_trim` 记录阈值、有效区间、排除指令数量和等待秒数。已有包含交接事件的 RLT 回合在重新载入时同样应用新筛选规则；原始记录始终保留，已完成的历史参数更新不会被“撤销”。

## 重启后的 CAN 恢复与启动日志

启动前会先只读核对两个 USB-CAN 适配器身份、接口状态和 1Mbps 波特率，失败时立即显示原因，不等待模型加载。若重启后接口未启用，可在待机界面点击“恢复CAN”，在弹出的终端中完成 sudo 认证；也可在部署目录执行 `sudo ./restore_rlt_can.sh`。脚本持有两路共享锁，只配置已核对身份的网络接口，不发送机械臂使能、回零或运动指令。完成后再点“启动本轮”。

每轮控制日志保存到 `logs/rlt_controller_时间_标识.log`。正常清理期间界面保持连接，收到明确退出通知后不再误发急停信号；意外断连与心跳超时仍走独立阻尼停止。模型服务使用异步信号处理正常退出，避免退出异常覆盖原始启动错误。
